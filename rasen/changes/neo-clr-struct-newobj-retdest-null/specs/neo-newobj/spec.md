# neo-newobj spec delta -- neo-clr-struct-newobj-retdest-null

## ADDED

### Requirement: A CLR value-type constructor redirect must land the constructed struct in the caller's local on the `call .ctor` lowering

Under `ENABLE_NEO_MODE`, a CLR value-type constructor that has an autogenerated Neo
redirect (`call.redirect` -> the generated `Ctor_*_Neo` stub), when invoked from IL via
the Roslyn `call .ctor` local-assignment lowering (C# `var v = new VT(args);` lowers to
`initobj; ldloca; <args>; push(this byref); call.redirect ctor` with dest `-`), MUST
construct the struct with the caller-supplied arguments and land it in the caller's local.
Concretely:

- The runtime `Call_Redirect` arm MUST propagate a byref-`this` callee param slot back to
  the caller after the redirect returns (call `CopyNeoCallThisBack`, mirroring the `Call`
  and `Callvirt_CLR` arms, with a pre-call snapshot of the write-back-flagged byref
  sources so a dest-aliasing clobber cannot corrupt the write-back read). A redirect with
  no byref slots (`PrimitiveByRefSrc == null`) is a no-op.
- The autogenerated `Ctor_*_Neo` stub MUST, for the `!isNewObj` (`call .ctor`) path, skip
  the in-frame `this` struct (`__curPrim += GetNeoValueTypeManagedSize(typeof(declType))`)
  before reading the constructor arguments (the byref `this` is dereffed into the first
  `__thisSz` bytes of the callee param region by `CopyNeoCallArguments`), and MUST write
  the constructed struct into the `this` slot at offset 0 via `WriteNeoValueType` so the
  runtime write-back propagates it to the caller's local. This mirrors the Legacy `Ctor_*`
  `!isNewObj` -> `WriteBackInstance` path.

Rationale: a struct constructor is void and mutates through the byref `this`; on the
`call .ctor` lowering the dest register is `-` (`Register1 = -1`), so `retDst` is `null`
and a stub that writes only to `__retDst` no-ops. The result reaches the caller's local
solely through the byref-`this` write-back. A stub that leaves the `!isNewObj` branch as a
`// TODO` (reading the zero-init `this` slot as the args) constructs a zero struct, and a
`Call_Redirect` arm that omits `CopyNeoCallThisBack` drops the result entirely.

NOTE: this requirement covers the into-local `call .ctor` shape (`crIsNewObj = false`,
`Operand4 & 0x2 == 0`). The as-value shape (`f(new VT(args))`, a genuine `newobj` the JIT
rewrites to `Call_Redirect` with `Operand4 & 0x2`, dest register present, `crIsNewObj =
true`) already lands its result via `__retDst` and is unaffected. A CLR struct ctor whose
result is then stored into a CLR-generic collection (e.g. `List<VT>.Add(new VT(...))`) has
a SEPARATE blocker on the `callvirt.clr` struct-arg marshalling path (out of scope; the
host receives a zero struct) -- this requirement does not cover that path.

### Requirement: The Call_Redirect arm must propagate byref write-back for redirect calls

Under `ENABLE_NEO_MODE`, the `ExecuteNeo` `Call_Redirect` arm MUST, after invoking the
redirect, call `CopyNeoCallThisBack` for any call whose `NeoCallParamMap` has
write-back-flagged byref sources (a struct-ctor / mutating-struct-instance-method `this`,
or a `ref`/`out` param), mirroring the `Call` and `Callvirt_CLR` arms. The write-back MUST
be gated on `PrimitiveByRefSrc != null` (a redirect with no byref params, e.g.
`Delegate.Combine`, is a no-op) and MUST use a pre-call snapshot of the byref sources so a
`Call_Redirect` whose dest register aliases a byref source register (the dest write
clobbers the byref bytes before the write-back reads them) still propagates correctly.
